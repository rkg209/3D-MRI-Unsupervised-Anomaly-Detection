# Unsupervised anomaly detection in 3D brain MRI

A reproducible **comparative study** of modeling paradigms: reconstruction models are trained on
**healthy** brain volumes only, then a held-out (possibly diseased) volume is flagged wherever it
reconstructs poorly. Every number below is generated by `make report` from files saved under
`artifacts/` — never typed in by hand — so it can never silently drift from what was actually
measured.

> **This is a research comparison of modeling paradigms. It is not validated for clinical use, is
> not a diagnostic device, and no output here should ever inform a patient-care decision.**

## The central finding

Reconstruction fidelity and detection quality are anti-correlated: the model that rebuilds a
held-out brain most faithfully (highest PSNR/SSIM) is the one that reconstructs the tumor too, and
so is the worst at flagging it — detection separability (Dice/IoU) is the target, PSNR/SSIM are
never optimized for and never a headline number.

This holds across the architecture x loss matrix (Spec 005) and is the question the diffusion
paradigm (Spec 013) sharpens further: does a *generative* prior resist rebuilding the tumor, or
fall to the same failure? Reporting that honestly, either way, is the point of this repo.

## Reproducibility

1. **Register for the datasets** (both require a free account):
   - Training (healthy): [OpenBHB](https://www.kaggle.com/datasets/rahulkumargop/openbhb/data)
   - Test (tumor-bearing): [BraTS 2020](https://www.kaggle.com/datasets/awsaf49/brats20-dataset-training-validation)
   - Point `MRI_AD_DATA` at the extracted directory, or drop it in `./data`.
2. **Fetch checkpoints** from the
   [Google Drive folder](https://drive.google.com/drive/folders/1ZVSV-4akGO8kbln2dH_ognXTFInPG2jH?usp=sharing)
   into `./checkpoints` (or set `MRI_AD_CHECKPOINTS`).
   **LFS-stub caveat:** the seven `legacy/*.pth` files checked into this repo are **Git LFS
   pointer stubs (133 bytes, no weights)** — they exist only as a structural reference. Real
   weights come from the Drive folder above.
3. **Verify before anything else:**
   ```bash
   make check-data
   ```
4. **Run the pipeline** (each target is a `make` recipe over Hydra config; override with
   `HYDRA_OVERRIDES="model=unetr +experiment=cluster"`):
   ```bash
   make slice     # Spec 000: one checkpoint, one volume -> Dice + figure
   make recon     # GPU, manual only: reconstruct the test split
   make eval      # score saved reconstructions, no GPU
   make classical # Spec 006: classical radiomic-features baseline
   make matrix    # Spec 005: architecture x loss table
   make paradigm  # Spec 007: Classical vs UNETR vs Diffusion headline table
   make report    # regenerate every table/plot + this README's scorecard, no GPU
   ```
5. **Determinism.** Every entry point calls `seed_everything(cfg.seed)` first and writes its git
   SHA, fully-resolved config, and seed to `artifacts/runs/<UTC-timestamp>/run_meta.json` — the
   provenance record every number in the scorecard above traces back to.

## The corrected baseline, and why it differs from the prior report's 0.6255

The prior notebook (`legacy/metric-uad.ipynb`) reported UNETR Dice **0.6255** / IoU **0.4551**.
That number is not trustworthy — it was produced by four independent bugs, reproduced here
*on purpose*, in an explicit bug-compatibility mode (`mri_ad.eval.legacy`), so the discrepancy is
demonstrated rather than asserted:

1. **The score list was re-initialized inside the per-subject loop** — the reported "average Dice"
   was the score of the **last subject only**, never averaged over the split.
2. **The BraTS segmentation was used raw** (labels `{0,1,2,4}`, never binarized) — a tumor-core
   voxel (label 4) contributed four times an edema voxel (label 1) to the Dice numerator. That is
   not a Dice coefficient.
3. **That same raw segmentation was resized with trilinear interpolation**, producing fractional
   "labels" (0.37, 1.84, …) multiplied straight into the numerator.
4. **Only depth-chunk 4 of 8 was ever scored** — seven-eighths of every volume was never looked
   at.

The corrected pipeline binarizes the segmentation, resizes it nearest-neighbour, accumulates
scores across every subject and every depth chunk, and shares one preprocessing function between
train and eval. The corrected Dice for the headline cell (UNETR + MSE-SSIM) is reported in the
scorecard above as `Corrected Spec 004 baseline Dice`, alongside its signed delta from 0.6255 —
which may well be **negative**, and is reported as-is either way (publishing a number known to be
inflated would defeat the point of a rigor-first rebuild).

## Classical-ML baseline (Spec 006)

`make classical` runs the honest control: engineered radiomic/texture features (first-order,
GLCM, gradient, GLRLM — 44/slice) into gradient-boosted trees, cross-validated on the identical
BraTS test split the reconstruction pipeline is scored on.

- **Operating granularity is slice-level**, not voxel-level: each 2D axial slice is one sample,
  classified tumor-bearing or not. This gives a clean ROC-AUC but **does not localize**, so it is
  **not directly comparable to the reconstruction pipeline's voxel-level Dice** — that gap is
  reported plainly, never glossed over.
- **PyRadiomics substitution.** PyRadiomics is fragile to build on some platforms, so this
  baseline uses `scikit-image` for GLCM/first-order/gradient features plus a hand-rolled GLRLM
  (skimage ships no run-length equivalent) instead. Every generated artifact records
  `features.library: scikit-image` / `pyradiomics_used: false` so the substitution is visible,
  not hidden.

## Mobility transfer (conceptual analogy only)

<!-- MOBILITY_START -->
The same "reconstruct the normal, flag the deviation" idea generalizes conceptually beyond brain
MRI: a model trained to reconstruct **normal driving trajectories** could, in principle, flag
**out-of-distribution mobility patterns** the same way this repo flags anomalous anatomy — a
poorly-reconstructed patch of trajectory as a candidate deviation instead of a poorly-reconstructed
patch of brain tissue. This is **a conceptual analogy, not a tested result**: no mobility or
trajectory dataset has been touched, no model has been trained on driving data, and no metric in
this repository says anything about that domain. It is included only because the underlying
"reconstruct normal, threshold the residual" mechanism transfers as an idea, and it is worth
naming as a direction, nothing more.

## Data use

Data and checkpoints are **user-supplied and never committed** to this repository — `data/`,
`checkpoints/`, `*.nii*`, `*.npy`, `*.pt`, `*.pth` are all git-ignored. No patient identifier,
on-disk scan path, or scan metadata is ever written to a log, artifact, or `run_meta.json`.
